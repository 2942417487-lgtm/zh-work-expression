# 工程交付与验收报告

报告帮助当前读者判断交付成果、验证依据和接续动作。结合用户指定的报告用途与项目格式使用以下规则。

## 先形成结论，再安排追溯材料

先从实际结果中提取：本轮具体变化、现在可用的能力、交付入口、最终验证与审查状态，以及影响验收的开放项。用这些信息写开头，避免仅以“实现、验证、独立审查完成”等通用状态代替成果。

聊天中的交付说明按当前使用、验收和接续需要选材，详细记录通过链接提供。来源中的实现细节、排除事项和未来能力，只有影响当前判断时才进入摘要；避免将长篇原记录逐段压缩后全部带入。需要保存完整任务报告时，将授权、基线、变更归属、命令与异常经过放在相应追溯部分；保真改写将原有实质信息完整保存在正文或附录中。

项目模板要求特定顺序或字段时遵循模板，在允许的位置增加具体结果摘要。一次性极短交付可直接写成一段。

## 用一份任务记录保存文件改动

需要持续交接的工程任务，沿用项目已有位置和格式维护一份任务记录，供人和 agent 共用。开头概述成果与当前状态，后面保存文件改动、验证依据和开放事项；聊天交付给出摘要与记录链接。项目另有交付要求时按要求组织。

依据实际差异或操作记录，让每个本轮变更文件都能定位：写明路径、变更类型、具体变化与目的。重命名列出原路径与新路径；同类批量文件可分组并链接完整清单。区分原有未提交改动与本轮修改，涉及记录、检查或比较的基线、分支和提交按实际状态注明。缺少差异证据时，先核对相关文件，再填写变更归属。

路径应能在目标工作区定位。仓库内的长期记录优先使用仓库相对路径或相对链接；聊天中的文件链接按宿主要求提供。已有命令、标识符和路径的原文保真规则继续适用，公开资料按发布要求处理个人路径。

## 为后续聊天留下记录链接

将任务记录链接、简短当前状态和接续事项放入项目已有的状态页、任务索引或约定入口，保留其他任务的信息。入口只维护定位信息，详细内容集中在任务记录。缺少既定入口时，在交付中给出记录路径，并说明后续从哪里读取；新建入口或修改指令文件沿用任务授权与项目约定。一次性短回复按实际用途决定是否保存记录。

接续已有任务时，先读取当前任务对应的记录，再核对当前分支、版本、相关文件和差异。根据实际状态处理记录中的待办，发现过期描述时同步更新；读取范围围绕本次接续需要确定。

## 验证按最终状态归纳

每批检查说明对象、所对应版本和实际结果。若检查后又修正代码，明确最终修正影响什么，以及之后执行了哪些检查；历史联合回归和最终定向回归分别记录。

根据任务说明选择回归范围的依据。完整回归、定向检查、跳过项、故障注入和真实环境检查使用各自准确名称。测试数量按原有批次记录，已复用的用例保持原批次关系。跳过项说明原因和覆盖影响，补验安排以本轮验收要求为依据；来源没有补验要求时，保持为测试覆盖说明。

失败后已解决的权限、输入或测试夹具问题放入过程记录。若问题改变最终行为、验收结论或复现方式，在结果部分保留其影响。配置值带上配置项名称；缩写和泛称指明实际对象。

先依据本轮验收要求判断剩余事项：要求内尚缺证据的项目，说明缺口、所需检查及执行条件；范围之外的能力按适用范围表达。来源只说“测试覆盖进程中断”时，保留这一测试条件，避免改写成“物理断电或系统隔离验收未完成”。未来能力放入路线图或任务来源。验证强度依据实际改动，避免为统一报告格式增加重复运行。

## 边界按含义合并

将同一项适用范围、排除能力或安全边界集中说明一次，并放在影响使用或验收的位置。具体 API 的拒绝行为、容量上限、错误恢复方式及安全要求保留完整。

Git 状态集中在 Git 状态处；过程中的隐私检查集中在对应结果处；故障测试的条件与局限紧随测试结果。研究、审查、测试和结尾引用共同边界时，使用交叉引用或简短指代。

准确的安全禁止条款和新增诊断信息按原意保留。不同原因产生的不同边界分别表达，合并以含义为依据。

## 以当前接续动作收尾

交付给用户 review 时，提供当前变更入口和少量值得优先核对的行为或证据。审查重点围绕本轮变化选取，已经说明的共同边界按需引用，避免在结尾重新列出。独立审查结果与用户 review 状态分别写清。连续开发时说明本轮变化与既有未提交工作的归属。

后续候选功能确需呈现时，放在当前接续动作之前或链接到路线图。当前交付的最后一段落在实际所需的审查、补验、决定或使用入口上。已完成且无需接续的任务，在结果交代完整处结束。

## 虚构示例

来源记录：新增内容存储模块；一次联合回归 72 项通过；后续修复仅影响裸 Git 仓库路径识别；修复后存储模块 19 项通过，路径拒绝用例包含其中；代码审查关闭 1 项问题，等待用户 review。

交付摘要可以写为：

> 已实现内容存储模块，可追加保存原始字节，并按引用读取和校验。用法见对应指南。
>
> 联合回归 72 项通过。随后修复裸 Git 仓库路径识别，修复后的存储模块 19 项测试全部通过，包含该路径的拒绝检查。独立审查的问题已关闭。
>
> 请在本轮变更中优先核对保存成功的判定和读取失败时的处理方式；变更入口见本轮差异。

来源若只写“裸库检查已修复”，需要先确认“裸库”指哪类存储。缺少检查记录时，报告该项当前状态和补验安排。
